# IT CV Writing Sri Lanka: What Software and Technology Recruiters Look For

An IT CV should make your technical direction and practical contribution clear. “IT professional” is too broad to explain whether you build software, support infrastructure or analyse systems.

Choose the role family first, then select relevant work. The same evidence will not carry equal weight for software development, support, security and business-analysis applications.

## Define the technical context

Describe the systems, users or products you worked with and the level of responsibility you held. Distinguish production experience from training, coursework and personal projects.

For support work, explain the types of issues and escalation responsibilities. For development, explain the component you built. For analysis, describe the requirements or process work you owned.

## Connect tools to delivered work

A technology list helps orientation, but experience should show what you did with those tools. Name the task, your contribution and the output or verified result.

An illustrative support example might describe documenting recurring access issues and preparing troubleshooting steps for the service desk. A development example might describe implementing validation for a customer-facing form. Both are clearer than “worked with technology.”

## Show professional working practices

Include relevant evidence of testing, documentation, incident handling, collaboration or change control. Use terms accurately and avoid listing methods merely because they appear in the advertisement.

If you claim ownership, explain its scope. Supporting a deployment is different from designing the release process or holding responsibility for the service.

## Make projects and credentials useful

Select a few projects relevant to the role. Add links when permitted and explain your contribution. Remove credentials, private configuration, customer information and proprietary code from anything you share.

List certifications with accurate status. Studying for a certification is not the same as holding it, and an old credential may require a status check before you present it as current.

## Review the application as a technical reader

Ask whether a colleague could understand your work without knowing your employer's internal language. Explain unusual acronyms and replace vague “end-to-end” claims with the actual stages you handled.

## Frequently Asked Questions

### Should I list every programming language I have tried?

No. Prioritise relevant capabilities and distinguish professional use from introductory learning or project exposure.

### Is a GitHub link required for every IT role?

No. Use a portfolio when it provides relevant, shareable evidence. Support, infrastructure and other roles may demonstrate value in different ways.
